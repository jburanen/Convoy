New deployment

      
    

    

      This looks like a new deployment, would you like to rename the default environment? 
    

    

      
      
      
    

    
 
      Environments are analogous to your Check Point management systems. Each related 
      group of management servers should have an environment defined here. That means any 
      primary management server and related SmartEvent and backup/HA servers. If you are 
      connecting to Multi-Domain, you should create one environment for the whole MDS 
      system, not one per domain.
    

  










  

    

      

      
    

    

  






  

    

      
Manage environments

      
    

    

      Environments are independent management estates — each has its own inventory
      of management servers and its own credentials. Edit a name and click
      Rename: servers, credentials, and job history move with it.
      Servers and deletion are managed on the Provisioning tab. An
      environment is always entirely an SMS estate or entirely a Multi-Domain
      (MDS) one — never a mix — so discovery and other commands know which
      variant to use.
    

    

    

      
      
    

  








  

    

      
Add credential set

      
    

    

      A named login set, stored encrypted at rest; secrets are never
      displayed again after saving. Give it an SSH password or a private key,
      plus an expert-mode password — SSH logs in as a plain clish user and elevates to
      expert only when a job needs it.

Discover servers

      
    

    

      Connects to a primary management server and enumerates the rest of the estate —
      other management servers, Log Servers, and SmartEvent servers via the Management
      API, plus MDS/MLM peers over SSH. Uses the credential set assigned to the primary.
      Review the detected roles and import the ones you want.

Discover firewalls

      
    

    

      Connects to the environment's primary management server and enumerates gateways
      and cluster members via the Management API — the scan itself uses the credential
      set assigned to the primary. Review the detected roles, choose the credential set
      each firewall should use, and import the ones you want. Imported firewalls are
      credential-tested straight away; any that fail to authenticate can be bootstrapped
      from their own row.

Bootstrap credentials

      
    

    

      Pushes each firewall's assigned credential set onto the device itself via the
      Management API. This rewrites the local admin account on every gateway listed —
      the same action as each row's own Bootstrap credentials button, run once per
      firewall.
